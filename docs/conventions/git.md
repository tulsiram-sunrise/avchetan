# Git & Workflow

The repository is not yet initialized — Phase 1 starts with `git init`. It will be hosted on **GitHub** as an open-source project under **AGPL-3.0-or-later** ([ADR-0018](../decisions/0018-open-source-agpl-github.md)). Treat every commit as public.

## Branches

- `main` is always green (lint, typecheck, tests pass).
- Work on short-lived branches: `phase-1/db-schema`, `feat/dock-ask-mode`, `fix/sync-ack-race`, `docs/adr-0015`.
- Squash-merge or rebase; keep history linear.

## Commits

Conventional Commits:
```
<type>(<scope>): <imperative summary ≤ 72 chars>

<why, not what — optional body>
```
- Types: `feat`, `fix`, `refactor`, `perf`, `test`, `docs`, `build`, `ci`, `chore`.
- Scopes: package/app names — `db`, `core`, `sync`, `shared`, `desktop`, `mobile`, `server`, `docs`.
- One logical change per commit; code + tests + doc updates together.
- Sign off every commit (`git commit -s`, Developer Certificate of Origin). External contributions without a sign-off are not merged.

## What never gets committed

`.env*` (except `.env.example`), API keys, sync tokens, signing certificates and **Android keystores**, SQLite databases, audio files, exported data, `node_modules`, build outputs (`dist`, `target`, `.expo`, `android/` generated by prebuild unless we decide to eject).

**No personal data, ever.** Real captures, real names, screenshots with real entries, or logs from real use must not enter the repo. Test fixtures and user-guide screenshots use made-up data. A secret scanner (e.g. `gitleaks`) runs in pre-commit and CI.

## Hooks & CI

- `lefthook` pre-commit: Biome check on staged files, `cargo fmt --check` when Rust changed, `gitleaks` on staged changes.
- GitHub Actions (workflow files live in the root `.github/workflows/`; code jobs set `defaults.run.working-directory: avchetan-code` and cache using `avchetan-code/pnpm-lock.yaml`):
  - `ci.yml` — install → lint → typecheck → test (Turbo cached) → `cargo clippy` → dependency license check (AGPL-compatible only) → secret scan; on `main` also build the desktop app (Windows runner).
  - `docs.yml` — build the VitePress site from `docs/`, fail on dead links/anchors, deploy to GitHub Pages.
  - `release.yml` (public release milestone) — on tag: signed Windows installer, signed APK, server image → GitHub Releases.
- Signing material lives only in GitHub Actions secrets and the owner's offline backup.

## Docs in PRs

A change that alters behavior described in `docs/` updates that doc in the same PR. Architectural decisions add an ADR.
