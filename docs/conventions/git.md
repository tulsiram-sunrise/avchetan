# Git & Workflow

The repository is not yet initialized — Phase 1 starts with `git init`.

## Branches

- `main` is always green (lint, typecheck, tests pass).
- Work on short-lived branches: `phase-1/db-schema`, `feat/dock-ask-mode`, `fix/sync-ack-race`, `docs/adr-0015`.
- Squash-merge or rebase; keep history linear.

## Commits

Conventional Commits:
```
<type>(<scope>): <imperative summary ≤ 72 chars>

<why, not what — optional body>
```
- Types: `feat`, `fix`, `refactor`, `perf`, `test`, `docs`, `build`, `ci`, `chore`.
- Scopes: package/app names — `db`, `core`, `sync`, `shared`, `desktop`, `mobile`, `server`, `docs`.
- One logical change per commit; code + tests + doc updates together.

## What never gets committed

`.env*` (except `.env.example`), API keys, SQLite databases, audio files, exported data, `node_modules`, build outputs (`dist`, `target`, `.expo`, `android/` generated by prebuild unless we decide to eject).

## Hooks & CI

- `lefthook` pre-commit: Biome check on staged files, `cargo fmt --check` when Rust changed.
- CI (GitHub Actions, once a remote exists): install → lint → typecheck → test (Turbo cached) → `cargo clippy` → build desktop (Windows runner) on `main`.

## Docs in PRs

A change that alters behavior described in `docs/` updates that doc in the same PR. Architectural decisions add an ADR.
